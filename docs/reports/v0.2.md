## 4. Trust scan

The scan reads each final candidate's README, `SKILL.md` files, install scripts, plugin hooks,
`package.json` lifecycle scripts and `.mcp.json` through the GitHub API, using the repo name only.
It sets `trust.flags` for these patterns:
- `pipe-to-shell`
- `prompt-injection`
- `hidden-instructions`
- `invisible-unicode`
- `base64-blob`
- `network-call`

Severity depends on context: the repo's own installer or a well-known one, a comment versus
executed code, a quoted example. A `high` flag drops the repo to the low tier. Injection-type
flags report file and line only and never echo the repo's text. Results are cached per repo until
the repo is pushed again. The rules were tuned against false alarms seen on 67 real repos.

**On this run, all 25 picks were scanned and 3 were flagged (16 flags):**

| repo | flags |
|---|---|
| oss-invisible/playwright_mcp | 2× `pipe-to-shell` **low**: the well-known `astral.sh` uv installer |
| elementalsouls/Claude-BugHunter | 1× `prompt-injection` **high** (SKILL.md, file and line only); 2× `network-call` **medium** (sends data to placeholder targets); 8× `network-call` low |
| SnailSploit/Claude-Red | 1× `prompt-injection` **high** (SKILL.md, file and line only) |

Both high-severity flags are on offensive-security skill bundles, whose content legitimately
discusses attack patterns. The scanner demoted both bundles to the low tier, which is the
intended conservative outcome. The skill tells Claude to skip anything with a high flag and to
say why.

**False-alarm fixes in D (`7a91426`):**
- Markdown `\|` in tables is not a shell pipe.
- A `curl … | sh` with no URL, host or variable describes the pattern; it doesn't run it.

The self-scan test requires that Tool Scout's own files raise nothing above `low`.

## 6. Decisions

- **Eval before tuning (A).** A frozen catalog plus labels makes ranking changes measurable and
  reproducible offline. Recall@25 is reported next to precision so precision can't be bought by
  returning nothing.
- **General rules only (B).** Precision comes from rules in `taxonomy.mjs`:
  - positional evidence (the name and first clause outweigh later mentions)
  - weak versus specific keywords
  - sense rules (A/B testing, CTF crypto, SQL injection, ReAct)
  - a separate `offensive-security` topic
  - tool affinity
  - a soft diversity penalty instead of a hard per-topic cap

  No rule names a repo, to avoid overfitting to the 55 labels.
- **Measured momentum, top 25 only (C).** The stargazers `star+json` API is tried first. GitHub
  now returns 404 on stargazer lists to anyone but the owner, so this is detected once (cached for
  a week) and `WatchEvent`s from the public events feed are counted instead. Other limits:
  - 4-way concurrency
  - stop at a rate-limit reserve
  - 20 h cache
  - partial windows shown as `+N+★`
- **Scan only the final candidates (D).** This keeps API cost bounded. Severity depends on context
  so that well-known installers don't drown out real findings. Repo text is never echoed for
  injection findings, so the scanner can't relay an injection into Claude's context.
- **Dismissals live in `recommend()` (E).** Dismissed repos also skip momentum lookups and the
  scan. Only repo names are stored.
- **Install hints are shown, never run (F).** The README the scan already fetched is reused.
  A command is rejected whole if it chains (`;`, `&&`, `|`, `$(…)`) or installs a different repo.
  A bare `npx` must be about this repo.
- **Exclude the running session by default (G).** The real run showed it is the request, not the
  user's work.
- **Privacy is unchanged.** The profile is counts only. Only fixed topic searches and public repo
  names go to GitHub.

## 7. Known issues

1. **Demoted repos still appear in the script output.** `recommend()` filters the low tier
   *before* the trust scan runs. Two repos demoted by the scan (BugHunter, Claude-Red) therefore
   stay in the top 25 with `trust: low`, even without `--include-low`. The skill skips them, but
   the CLI and JSON don't. Fix: re-filter, or backfill from the next candidates, after
   `applyFlags`.
2. **8 of 25 picks show estimated momentum.** Six have no momentum cache entry at all. They
   probably entered the top 25 after the momentum re-rank, but this isn't verified. Two
   (oil-oil/beautify-github-readme, lemonadesaltbagel/crab) have fresh cached events measurements
   that weren't applied to the output. The cause hasn't been investigated.
3. **Kind classification is loose.** Examples:
   - mobile-next/mobile-mcp is labeled `skill` but is an MCP server.
   - LibreChat-AI/LibreChat is labeled `skill`.
   - drawdb-io/drawdb (an online diagram editor) is labeled `mcp-server`.
4. **Install-hint edge cases:**
   - kyy-logs/code-review-gate-skill's extracted command targets `--agent codex`, not Claude Code.
   - wshobson/agents gets one plugin (`python-development`) out of a multi-plugin marketplace.
   - 10 of 25 picks have no real install command and fall back to a generic hint.
5. **A thin history gives a long tail.** With 4 sessions, picks 6–25 rest on topics seen in a
   single session (finance, offensive-security, database, devops).
6. **Debatable on-topic matches remain.** Examples: a Windows sandbox for a macOS/JS user, and a
   stealth/anti-bot Playwright fork. These match the eval's residual errors.
7. **The eval set is small (55 repos)**, and its labels were built partly from v0.1 shortlists.
8. **Validator warnings:** there is no marketplace `description` and no plugin icon.
9. **The trust scan is a heuristic.** It doesn't follow scripts that installers download or scan
   MCP server source. No flags doesn't mean safe.
