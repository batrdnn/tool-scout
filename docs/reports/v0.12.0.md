# Tool Scout v0.12.0: security review before v1.0

Ranking is still frozen: no ranking file changed (the fixes are in `installer.mjs`, `builder.mjs`,
`scan.mjs` and `cli.mjs`, none frozen; the skill edits are outside steps 2-4 of
`skills/scout/SKILL.md`). Every fix had its tests written first and seen failing before the code.
For two of them (the build-plan tamper check in `283aafc` and the case-collision block in
`8b32b6f`), that was confirmed by stashing the fix and rerunning. The command and privacy attack
tests (`8b385fa`, `5a9a0b9`) passed straight away: those attacks already failed against the code,
and the tests now guard that.

The full review (threat model, 8 high, 9 medium and 6 low findings, the attacks that held, and the
red team's attempts) is in [docs/security-review.md](../security-review.md).

## Found by the red team and the security-guidance review

A fresh agent, with no view of the code's intent, attacked the code before the fixes. Five of its
attacks worked: inline plugin hooks and MCP servers missing from the plan, a padded hook command
hiding `rm -rf`, an edited plan file, a fake `END REPO TEXT` line, and newline file names faking plan
lines. Five were partial and four were blocked. Its results are listed in section 4 of the review.
The security-guidance plugin reviewed each fix commit. From its findings came the line-by-line
quoting in `head`, escaping by Unicode category, every field of MCP servers and http hooks,
case-folded plugin lookups and the case-collision block, and content-based binary detection.
