# Tool Scout v0.5: standalone trust check

Ranking is frozen for the testing period. This release adds a trust check and an audit
alongside it. There are four items, each with tests written and run red first, committed one per
item. `v0.4.1` is tagged on `1ccad28`. All numbers come from runs on 2026-11-23 at `4da40dc`.

## What changed

| item | commit | change |
|---|---|---|
| 1 | `af049ef` | `scout.mjs check <owner/repo \| URL> [--json]` and the `/tool-scout:check` skill (`skills/check/SKILL.md`). It runs the existing content scan plus metadata trust and the Claude Code install hint, and gives a verdict: **safe-looking** / **review** / **do not install**. Injection-type flags carry file:line only. The skill explains the result plainly and always ends with "no flags doesn't mean safe" |
| 2 | `9e4585f` | `scout.mjs audit [--json]`: a **local** scan of `~/.claude/skills`, installed plugin folders (`installed_plugins.json` → `installPath`, or `plugins/cache/…`), and MCP server commands from `~/.claude.json` and project `.mcp.json` files. Reports medium and high flags only, with file:line. It never shows excerpts, MCP args or env |
| 3 | `51681e6` | `eval:e2e --samples N` (default 1). Each sample is cached separately (sample 1 reuses the original key), and the output shows mean [min–max] |
| 4 | `4da40dc` | README: a "Check before you install" section. TESTING.md is unchanged |

**Verdict rules:**
- **do not install:** any high flag.
- **review:** any medium flag, an archived repo, low metadata trust, or nothing readable.
- **safe-looking:** otherwise.

**Supporting changes and bugs:**
- `slim` is now exported from `crawl.mjs`, which is not a frozen file.
- The no-network CLI test found a bug in audit: a project `.mcp.json` was read twice, through
  `/var/…` and `/private/var/…`. Paths are now deduplicated by realpath.

What this shows:
- **BugHunter:** good metadata didn't save it; the content flags decided the verdict.
- **The four clean repos:** they had no flags, but the scan read only 2–5 of their files
  (README, package.json, SKILL.md files, configs). That's why both the CLI and the skill repeat
  that no flags doesn't mean safe.

## Tests and validation

- **`npm test`:** 128 tests, 128 pass, 0 fail, 0 skipped (v0.4.1: 117). The new tests cover:
  - `check`: verdicts, URL input, metadata, the install hint, README fallback, errors, and that
    injection flags never echo repo text in JSON or text output.
  - The check skill file, which is also in the self-scan.
  - `audit`: skills, plugins and MCP findings; medium and high only; no MCP args or env shown.
  - **Zero network calls for `audit`:** in-process with `fetch`, `net` and `tls` patched to
    count calls, and in a child process with networking disabled through `--import`.
  - `--samples`: separate caches, mean, min and max, and that sample 1 equals a plain run.
  - The README section.
- **`npm run eval:e2e -- --samples 3 --cache-only`:** passes without calling the judge.
- **`claude plugin validate .`:** ✔ Validation passed. It lists both skills
  (`tool-scout:scout`, `tool-scout:check`). The warnings are the same 3 as before: icon
  (skipped) and two untracked `.DS_Store` files (git-ignored).
